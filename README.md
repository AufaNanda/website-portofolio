# Web Aufa — Portfolio

A one-page cinematic portfolio: fixed header + six sections (Profile, Skills &
Technologies, Experience, Projects, Certifications, Contact) plus a footer,
built as a React SPA with a Star Wars Jedi: Fallen Order–style HUD aesthetic —
dark, cyan-accented, JetBrains Mono, soft eased motion throughout.

## Stack

- **React 18** + **Vite 5**
- Plain CSS animations (`@keyframes`, `transition`) and SVG — no animation
  library
- [`ogl`](https://github.com/oframe/ogl) — lightweight WebGL, used only by the
  cursor glow effect
- Google Fonts: `JetBrains Mono` (HUD text) and `Parisienne` (the signature)

> Dependencies were checked against `LIBRARY_HACKED.txt` (local, not
> published — see below) — none of the compromised packages are used,
> directly or transitively, by this setup.

## Run it

```bash
npm install
npm run dev
```

Then open http://localhost:5173 (Vite is configured to open it automatically).

Build for production:

```bash
npm run build
npm run preview
```

## Deploy

Live at **https://aufananda.github.io/website-portofolio/** once the first
push lands. `.github/workflows/deploy.yml` builds and publishes to GitHub
Pages automatically on every push to `main` (also runnable by hand from the
Actions tab). One-time setup on GitHub: **Settings → Pages → Source → GitHub
Actions**.

Because the site lives under the `/website-portofolio/` sub-path rather than
the domain root, every asset URL is built through `import.meta.env.BASE_URL`
(see `src/lib/paths.js`, and `%BASE_URL%` in `index.html`) instead of a
hardcoded `/xxx` string — that's what `vite.config.js`'s `base` option
controls, and it's what makes `npm run dev` and the deployed build resolve
images/PDF/favicon the same way.

## Folder structure — what's published, what isn't

```
index.html, vite.config.js, package.json    → published (needed to build)
README.md, .gitignore                       → published

src/                                        → published (all source code)
  main.jsx, App.jsx, index.css
  assets/Aufa_PP.jpg                        → imported directly by ProfileSection
  components/                               → one .jsx + .css per section

public/                                     → published (served as-is; Vite
                                               copies this verbatim into the
                                               build output, so any deploy —
                                               GitHub Pages, Vercel, Netlify —
                                               needs it in the repo)
  skills/, badges/, experience/,
  projects/, certificates/, *.pdf, *.jpg    → the actual images/PDF the site
                                               loads at runtime

design-source/                              → NOT published (gitignored)
  Badge/, certificates/, experience/,
  projects/, skills/, references/,
  Aufa Ekananda-resume.pdf, Aufa_PP.jpg     → original/raw assets, already
                                               copied into public/ or
                                               src/assets/. Kept locally only
                                               so future edits (recrop, swap
                                               a badge, etc.) have a source
                                               to work from — no reason to
                                               duplicate that weight in the
                                               public repo.

.agents/, .claude/, skills-lock.json        → NOT published (gitignored) —
                                               local AI-tooling/skill caches,
                                               unrelated to the site

LIBRARY_HACKED.txt                          → NOT published (gitignored) —
                                               a personal working note

node_modules/, dist/                        → NOT published (gitignored) —
                                               regenerated by npm install /
                                               npm run build
```

**Rule of thumb:** if the running site reads a file at runtime (`src/` or
`public/`), it's published. If a file only existed to *produce* something
already sitting in `src/`/`public/`, or it's tooling/notes for working on the
project, it's gitignored.

This repo hasn't been initialized with git yet — run `git init` when you're
ready to start committing; the `.gitignore` above is already set up to keep
the right things out from the first commit.

## What maps to the reference

The Profile section recreates the "movie mode / character screen" layout
from the original mockup (kept in `design-source/references/`), using
`Aufa_PP.jpg` as the portrait — panel headers, a role/link list, cycling
trait values, a signature, and a bottom HUD bar. Skills renders a
constellation-style skill tree (`skill_tree.png` reference), Experience is a
centre-spine timeline with floating crystal frames, and Projects /
Certifications use fluttering banner cards (`Project_Structure.png`
reference).

## Animation

Everything is soft, slow, and eased — scene fades, staggered reveals on
scroll, ambient loops (bokeh drift, rim-light breathing, film grain, crystal
float, banner flutter). All of it is disabled under
`prefers-reduced-motion: reduce`.
